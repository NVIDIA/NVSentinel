### Migration to ko

**What we changed**:

- Migrated **11 out of 13** Go-based modules from Docker builds to [ko](https://ko.build)
- Exceptions: 2 modules remain on Docker
  - `gpu-health-monitor` (Python-based with DCGM dependencies)
  - `syslog-health-monitor` (requires syslog libraries)
- Declarative config [.ko.yaml](.ko.yaml)
- Chainguard's distroless static base
- Multi-platform; (`linux/amd64`, `linux/arm64`)

**Benefits**:

| Metric | Before (Docker) | After (ko) | Improvement |
|--------|----------------|-----------|-------------|
| **Image Size** | 50-80 MB | 38-45 MB | **~25% reduction** |
| **Vulnerabilities** | 100s (10+ critical/high) | **0 CVEs** (today) | binary and base, nothing else |
| **SBOM** | additional step | **part of build** | CycloneDX format in attestation |
| **Build Time** | Slower | **Faster** | Multi-platform builds optimized |

### SLSA Level 3 Provenance

> "SLSA (Supply chain Levels for Software Artifacts) 

Security framework based on Google's internal attestation, released by Linux Foundation
Think of it as a nutrition label for software. It tells you exactly how and where your software was built.

**Layers**:
- **SLSA L1**: Basic provenance exists
- **SLSA L2**: Provenance is signed
- **SLSA L3**: Provenance is generated by a **trusted, isolated build system** ← **We're here**
- **SLSA L4**: Requires two-party review (future goal)

**What we implemented**:
- All 13 images (ko + Docker) get **SLSA v1.0 provenance attestations**
- Generated by GitHub Actions using `actions/attest-build-provenance@v3`
- Attestations are:
  - ✅ **Cryptographically signed** (keyless via Sigstore/Fulcio)
  - ✅ **Stored with the image** in the OCI registry
  - ✅ **Logged in Rekor** transparency log (immutable, public)
  - ✅ **Verifiable by anyone** - no NVIDIA credentials needed

**Demo**:

#### UI

https://github.com/NVIDIA/NVSentinel/attestations

#### CLI

```shell
export DIGEST="ghcr.io/nvidia/nvsentinel/fault-quarantine-module@sha256:397d1c3965828df9729817c1f3a42a94a8c93f06ae1445e29bea98ba7edb26e2"
```

GitHub

```bash
gh attestation verify "oci://${DIGEST}" \
  -R NVIDIA/NVSentinel \
  --bundle-from-oci \
  --signer-workflow 'NVIDIA/NVSentinel/.github/workflows/publish\.yml@refs/heads/main' \
  --cert-oidc-issuer https://token.actions.githubusercontent.com \
  --format json --jq '.[].verificationResult.summary'
```

Cosign

```bash
cosign verify-attestation "${DIGEST}" \
  --type slsaprovenance1 \
  --new-bundle-format \
  --certificate-identity-regexp '^https://github\.com/NVIDIA/NVSentinel/\.github/workflows/publish\.yml@refs/heads/main$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  | jq -r '.payload' | base64 -d | jq .
```

**What you'll see**:

- SLSA predicate type: `https://slsa.dev/provenance/v1`
- Builder ID: `https://github.com/actions/runner/...`
- Build invocation: commit SHA, workflow name, trigger
- External parameters: repository, ref (branch/tag)

> Anyone can run this verification - it's public and requires no secrets

#### Cluster

Policy: [image-admission-policy.yaml](distros/kubernetes/nvsentinel/policies/image-admission-policy.yaml)

> Namespace `no-match-policy=allow` (only verify NVS images)

**Talking points**:
- ⚡ **Automatic enforcement** - no manual verification needed
- 🎯 **Scoped to NVSentinel** - doesn't block third-party images (MongoDB, Prometheus, etc.)
- 🔒 **Zero-trust deployment** - only verified images run
- 📊 **Audit trail** - Rekor provides public log of all signatures

## Developer Experience

Goal: Remove contribution friction (**zero to first PR in under x minutes**)

### Simple Dev Environment Setup

**Before** (implied): Manual installation of 15+ tools, version mismatches, broken builds

**After**:

```bash
git clone https://github.com/NVIDIA/NVSentinel.git
cd NVSentinel
make dev-env-setup  # ← Magic happens here
```

**What it does**:

1. Detects your OS (macOS/Linux) and architecture
2. Installs `yq` for version management
3. Installs all required tools based on `.versions.yaml`:
4. Configures Python gRPC tools
5. Verifies installation

[.versions.yaml](.versions.yaml)

**Demo**:

```bash
make show-versions
```

> Drives local dev, Tilt, and CI/CD. Change once, apply everywhere

**The problem we solved**: Version drift between:
- Local Makefile
- Tiltfile (local k8s dev)
- GitHub Actions CI
- Dockerfiles


### Convention-Based Development

**Standardized Makefile targets** across all 13 modules:

```bash
# Every module supports these targets
make test          # Run unit tests
make lint          # Run linters (golangci-lint, black, shellcheck)
make build         # Build the module
make build-ko      # Build with ko (for Go modules)
make build-docker  # Build with Docker (for Python/special modules)
make clean         # Clean build artifacts
make help          # Show all available targets
```

> New contributor? Learn once, apply everywhere. Same commands for Go, Python, doesn't matter
